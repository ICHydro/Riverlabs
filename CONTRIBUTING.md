# Contributing to Riverlabs

Thank you for your interest in contributing to the Riverlabs repository. Please take a moment to review these guidelines before getting started.

## Before you start

Please check [existing issues](https://github.com/ICHydro/Riverlabs/issues) and [pull requests](https://github.com/ICHydro/Riverlabs/pulls) to avoid duplicating work. Do not work on an issue if it is already assigned. Collaborators are welcome to assign themselves to existing issues.

If no related issue exists, open one first to discuss the approach before starting work on a pull request.

## Creating issues

When creating an issue:

- Provide a clear description of the problem or feature request
- Include steps to reproduce the problem (for bugs) or use cases (for features)
- Mention your environment if relevant (e.g., hardware, OS and software versions)

## Making changes

### For collaborators

- Create a feature branch from `main` for your work
- Push to your branch and open a pull request

### For non-collaborators

- Fork the repository
- Create a feature branch on your fork
- Push to your fork and open a pull request to this repository

## Commits and pull requests

- Use clear, descriptive commit messages
- Keep commits logically organized
- Before submitting a pull request, ensure:
  - Your code compiles successfully
  - Static analysis checks using `pio check` are passing (if using PlatformIO)
  - Pre-commit checks are passing
- When opening a pull request:
  - Provide a brief description of your changes
  - Include the issue the pull request is addressing
  - If the pull request is in **Draft**, mark it as **Ready for review** when ready for feedback
  - Request review from @ICHydro and @stephwills

## Code review

All pull requests require approval from two reviewers before merging. Reviewers will provide feedback, and authors are expected to address comments or discuss concerns.

## Becoming a collaborator

If you are a member of the ICHydro research group and believe you should have collaborator access, please request access from @ICHydro.
